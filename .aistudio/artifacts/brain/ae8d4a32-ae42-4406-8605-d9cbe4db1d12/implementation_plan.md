# Vercel環境での404エラー解消およびAPIキー直接入力（BYOK）対応計画

## 1. 課題の根本原因
- ユーザーは Vercel に静的サイトとしてデプロイしており、Vercel 側には環境変数を設定せず、**ウェブアプリ画面上で API キーを入力して使用する運用（BYOK）**を行っている。
- 直前の変更で全 API 呼び出しがサーバーエンドポイント（`/api/gemini/translate-batch` 等）へ固定されたため、Vercel 上でバックエンドが稼働していない静的環境では **404 Not Found** となり、アプリが停止してしまっていた。

---

## 2. 解決アプローチ
Vercel などの静的ホスティング環境でも、ウェブアプリに入力した API キーを用いて**ブラウザから直接 Gemini API を呼び出せるクライアントサイド自己完結型（ハイブリッド）構成**に移行します。

### ステップ 1: API キー設定モーダルとUIの復活（`components/SettingsModal.tsx` & `App.tsx`）
- ヘッダー右上に設定アイコン（歯車）を復元。
- ユーザーがスマートフォンやPCのブラウザから自分の Gemini API キーを入力・保存（`localStorage`）・クリアできる設定モーダルを実装。
- API キー未入力時には分かりやすい案内バーを表示し、ワンタップで設定画面を開けるようにする。

### ステップ 2: クライアント側ダイレクト Gemini 呼び出しの実装（`services/geminiService.ts`）
- 端末に入力された API キーを使用して、ブラウザから直接 `@google/genai` または REST API で Gemini を呼び出すロジックを実装。
- **モデル**: 応答速度が最も高速な `gemini-3.1-flash-lite` を使用（思考遅延最小、1〜2秒で応答）。
- **フォールバック設計**:
  - `/api/gemini/translate-batch` へリクエストを試行し、404 またはオフラインの場合は即座にクライアント側の API キー直接呼び出しへとシームレスに自動フォールバック。
  - どちらの環境（フルスタックサーバー環境 / Vercel 静的配信環境）でも100%確実に動作する耐障害性を確保。

### ステップ 3: 一括翻訳・語尾補完・音声生成の高速化を維持
- 3件ずつのチャンク分割（プログレス表示「翻訳＆補完中 1/3...」）を維持。
- 15秒タイムアウトによる無限待機防止。
- 音声読み上げ（TTS）もブラウザから直接生成し、キャッシュを活用してスムーズに再生。

---

## 3. 動作検証計画
1. **ローカルおよびビルド検証**:
   - `npm run build` および `compile_applet` でビルドが成功することを確認。
2. **クライアントダイレクト実行テスト**:
   - サーバー API がなくてもブラウザから直接 Gemini API（翻訳・補完・音声）が実行できることを検証。
3. **404エラー耐性テスト**:
   - `/api/gemini/*` が 404 を返した場合でも、画面側でエラーにならず即座に端末入力キーで翻訳が続行されることを確認。
